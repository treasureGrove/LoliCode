# CC Switch 功能退出边界

LoliCode 的产品入口只有主 Agent 工作台、统一渠道与模型、用量和设置。外部客户端是渠道配置目标，不再各自拥有一套供应商管理应用。

## 本轮删除与收束

- 删除 CC Switch 3.x→4.x 的“新版布局”启动弹窗、逐客户端查询是否有供应商的门槛，以及该弹窗跳转上游 release 的逻辑。欢迎与 LoliCode 自己的更新摘要仍保留；更新摘要不再受旧布局标志阻塞。
- 删除通用设置中旧“显示应用”“项目切换器”“供应商搜索”控件。这些偏好不再影响统一侧栏，故不继续展示失效开关。
- 托盘不再列出独立客户端的供应商切换子菜单；保留打开 LoliCode、轻量模式、官网与退出等平台操作。官网指向 `https://lolicode.com/`。
- 旧 provider、OpenClaw 工作区/环境/工具配置入口统一进入渠道中心；旧 MCP、Skills、提示词、会话、Hermes 记忆独立页入口统一进入主 Agent。旧托盘添加供应商/需要路由事件不会再打开旧编辑器。
- `apps` 是统一渠道中心内“本地 Agent 工具”卡片的兼容别名，保留其直接定位意图，不恢复原 CC Switch 应用页。
- 从 `App.tsx` 删除旧供应商列表/新增/编辑、切换模式、客户端工作区、独立 MCP/Skills/提示词/会话、OpenClaw/Hermes 专页的 renderer、重型静态导入和配套控制器。启动不再预取所有客户端供应商，侧栏也不再查询各客户端模式和 Claude Desktop 供应商。启动路由恢复失败直接提示进入统一渠道检查，保留原生恢复能力。
- 生产外壳回归覆盖旧导航迁移、统一入口、启动不改配置、渠道草稿确认与操作锁、快捷键、后台同步、迁移通知、更新和导入刷新；不再通过测试专用路由重新暴露退出页面。

## 有意保留

- provider 数据库、客户端配置读写、迁移、备份、导入导出与配置目录覆盖，防止更新丢失用户渠道及历史。
- 原有客户端使用量导入，以及这一轮新增的 WorkBuddy/DSH/ZCode/MiMo 导入。
- 主 Agent 自己的技能、MCP、插件、工作流与记忆管理。
- 旧导航存储键、设置字段和托盘内部标识用于兼容，退出控件不代表删除用户文件或重置配置。
- 原许可、版权与代码来源声明。

`App.tsx` 中的旧页面控制器已删除。部分旧组件文件仍作为共享表单、配置编辑和独立单元测试依赖保留，未批量删除目录或配置读写后端；这些文件不再由 App 的旧页面分支静态引入。后续清理先逐项确认统一渠道、设置、导入和客户端 writer 的引用，再删除不再依赖的源码。

本轮本机生产构建的主要 JavaScript 从 5,184,203 字节降至 2,856,528 字节，约减少 44.9%。构建仍提示大 chunk；这不是后续分包工作的替代。
