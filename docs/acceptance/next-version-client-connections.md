# 下一版：Codex / Claude 原生与 LoliCode 路由切换

状态：开发分支功能，尚未打包发布；官网现有 4.0.21 不含本次改动。

## 行为

- “模型与渠道”的一键配置区域新增 Codex、Claude Code 两张连接卡片，分别显示实际配置状态，可独立选择“原生配置”或“LoliCode 路由”。其他工具继续使用模型配置流程。
- 状态从工具当前配置文件读取，重新进入页面或点击刷新后重新确认；写入失败时也重新读取，不把按钮点击当作切换成功。无法解析配置或处于旧路由模式时显示待确认及处理提示。
- 切换到 LoliCode 路由，仅配置所选工具；使用已保存的可用 API 模型，首次切换也可直接配置。不会修改一键配置的目标列表，也不会改写其他工具。只有原生订阅、没有可用路由模型时，路由按钮不可用。
- 首次从原生转入路由前，在本机现有配置数据库中保存该工具的原生记录。重复应用路由不会用网关凭据覆盖原生记录。用户切回原生并修改本地配置后，下次转入路由会更新记录。
- 切回原生恢复切换前的地址、Key 或原生登录配置，沿用已有配置写入与认证恢复机制，并保留路由期间新增的 MCP 等无关设置。Codex 的 API Key 可能按现有写入机制调整存储位置，验收以有效凭据与地址一致为准。
- 原生恢复不依赖模型目录正常加载。旧版已经接入路由、但从未保存原生记录时，退回工具官方登录配置；不能恢复从未备份的旧自定义地址或 Key，可能需要在原工具重新登录。界面会说明此情况。
- 切回原生不会关闭共享网关，避免影响其他工具与主 Agent。使用 LoliCode 路由时需要本体在后台运行；原生配置不依赖它。
- 前端只接收状态和提示，不接收原生记录、Key 或登录令牌。打开中的 Codex / Claude 会话可能仍使用内存里的旧配置，切换后需新建会话或重启对应工具确认。
