- [ ] MiMo Code 重新应用配置后能正常启动和调用；只有部分上下文信息的模型不产生残缺的 `limit` 字段。
- [ ] MiMo 原有自定义渠道及无关设置保留，重复应用不新增重复条目。

- [ ] ZCode 有用户自建同名模型／提供商时，不覆盖用户内容；检查冲突处理后新配置可正常调用。

- [ ] Claude Code 经路由选择思考档位后执行同一任务，确认工具调用、回复和长输出正常；主观效果请反馈渠道、模型及复现步骤。

## 模型上下文

先在「模型与渠道」刷新 GitHub Copilot 模型目录。旧缓存不会自行变成新目录；只有上游声明多个档位的模型才显示多档选择。

- [ ] 支持的 Copilot 模型能看到标准与长上下文预设，输入预算、总窗口、最大输出分开展示。
- [ ] 切换预设后会话采用对应预算；切换会话、重启和刷新目录后选择仍保留。
- [ ] 没有多档声明的模型保持单一窗口，不凭模型名称编造额度。
- [ ] 刷新目录失败时已有模型和所选档位保留，失败提示可理解。
- [ ] 其他声明了多上下文档位的渠道同样可切换；渠道未声明时不假定支持。

## 用量、应用与品牌

- [ ] 在 LoliCode 自己的主 Agent 发送一次请求，结束后用量页面能找到该请求。
- [ ] 按 LoliCode／外部 Agent、渠道分别筛选，结果对应实际记录；通过网关的同一请求不重复计费。
- [ ] 缺少价格时费用保持未知，不把未知显示为零消费。
- [ ] 本地 Agent 管理能识别 WorkBuddy、DSH、ZCode、MiMo、CodeBuddy 和 Qoder；ZCode 图标为黑白 Z。
- [ ] CodeBuddy 可应用已有模型配置；Qoder 本轮为本地管理，不等同于已支持其模型配置。
- [ ] 新安装的产品名、网关和日志显示 LoliCode，旧安装的数据仍被读取。

## 酒馆与 UE

- [ ] 添加酒馆应用后看到内置人物卡，预览人物、创建会话和离线开场均可用。
- [ ] 配置模型后继续人物对话，角色设定和会话历史保留。
- [ ] 在实际 UE Editor 项目安装配置桥，检查模块编译、重启 Editor、项目识别和连接状态。
- [ ] UE 桥连接后执行一次只读查询，再在测试项目执行一项可撤回操作并核对结果。
