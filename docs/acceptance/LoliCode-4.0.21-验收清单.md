# LoliCode 4.0.21 人工验收清单

更新日期：2026-10-18。适用包：Windows x64 正式版 **4.0.21**。安装包源码：`2c0723825e5e11e4f4670a680d50262f400484e2`。

这是给实际操作使用的清单，不是“所有功能已经完成”的报告。所有复选框先留空；自动化测试通过不代替你在另一台电脑上的实际操作。后续迭代继续沿用条目编号记录问题，换版本时登记新的版本号。

## 怎么记录

- 通过：勾选该项，并记录实际版本。
- 失败：保持未勾选，在条目后写 `失败：实际现象`。
- 环境不具备：写 `待条件：缺少什么`，不算通过。
- 已标注“待实现／待发布”的项目：先保留，后续实现或提供验收包后再测。
- 界面入口找不到、按钮点了没反应，也记录为问题，不要为了跑完流程跳过去算通过。
- 反馈可以只发编号，例如 `G04 失败：点打断发送后，旧任务继续改文件`。截图和日志不要包含完整 API Key、登录令牌或 SSH 私钥。

## 2. 主 Agent、长任务和对话交互（A01／A02）

建议在独立测试项目中，让 Agent 完成一个小型 HTML／Three.js 场景，再继续修改；例如黑洞或骑自行车的鹈鹕。记录模型、档位和真实请求轮数。

- [ ] G01 · 基础执行闭环。让 Agent 新建页面、修改文件、运行必要检查并总结。预期：确实产出文件和检查结果，不只是口头说完成。
- [ ] G02 · 长任务。安排需要持续读取、修改、验证的有界任务，实际跨过 24／32 轮工具循环。预期：不会因固定累计轮数直接终止。注意：一次调用生成 40 个文件，不等于完成了 40 轮验收；没有实际跨过阈值就记“待条件”。

- [ ] G05 · 执行中切配置。在执行中修改模型、思考档位和权限，再继续任务。预期：选项可操作；下一次相应请求／权限检查生效，已发送请求不被伪装成已换模型。

- [ ] G07 · 提问选择。让 Agent 遇到需要选择方向的需求。预期：出现可选项／补充输入，提交后继续；切换会话不会把答案送错任务。
- [ ] G08 · 默认实现。开始普通开发任务。预期：不再要求选择“分析／实现”，默认可按权限执行。

- [ ] G11 · 中断和失败。测试取消、模型连接失败，再继续同一会话。预期：已有文字保留，错误在当前任务内清楚呈现；没有永远“正在回复”、假成功或重复执行已完成操作。

## 8. 工作流、定时和闲时任务（A09／A10）

## 9. 远程项目与多项目并行（A11／A21）

SSH 需要自有测试主机，WSL 需要本机已有发行版。缺少其中一种环境，不影响记录另一种的结果，但不能算两者都通过。

- [ ] R01 · SSH 项目。连接测试主机并打开远端工程。预期：主 Agent 能读取远端文件、运行命令、做一次受控修改；本机同名文件不被误改。
- [ ] R02 · 远端预览与工作流。预览远端文件，运行该远端项目工作流／定时任务并取消一次。预期：目标、结果和取消回执均属于远端项目。
- [ ] R03 · 断连恢复。任务中断开测试连接，之后重连。预期：明确显示断连，记录保留；不一直空转、不把未成功的操作写成成功，也不盲目重做副作用。

## 10. 用量与费用（A12／A23）

先区分三种数据：上游实际回报的 token／缓存、本地记录或导入、官方订阅／账单。未知价格不应显示为免费；个人 Copilot 总账单也不能直接当作 VS Code 或 Visual Studio 各自费用。

- [ ] B01 · 会话单行统计。完成数次真实请求后观察输入框底部。预期：一行展示本会话统计，实际已回报的数据不无故变成 `—`；缺失字段清楚区分“未回报”和 0。
- [ ] B02 · 缓存和轮次。使用能返回缓存用量的渠道连续请求。预期：缓存读写／命中与真实上报相符，轮次含义稳定；不能把一次多工具调用随意算成多次模型请求。
- [ ] B03 · LoliCode 自身。筛选 LoliCode 和一个时间范围。预期：本体请求计入相应记录，与会话数据可以解释地对应。
- [ ] B04 · 按应用／渠道筛选。分别选择 WorkBuddy、DSH、ZCode、MiMo 等已有数据的应用，再按渠道查看。预期：筛选有效，不把不同来源费用重复叠加；不支持来源应明确提示。
- [ ] B05 · 导入去重。刷新或再次导入同一批本地记录并重启。预期：相同记录不重复计费，历史数据保留；导入记录不冒充实时官方账单。
- [ ] B06 · 趋势／热力图。切日期并悬停每日方块。预期：深浅、日期、汇总和提示一致；无数据与零消耗可区分。
- [ ] B07 · Copilot 个人订阅。核对官方可取得的额度／账单与本地 VS Code、Visual Studio 记录。预期：来源明确；没有编辑器级官方拆分时明确写无法拆分，不能猜测金额。
