# 下一版：多档上下文窗口验收

状态：开发分支功能，尚未打包发布；官网现有 4.0.21 不含本次改动。

## 行为

- 模型目录保留明确返回的多个窗口，不再只保留一个数值。支持上下文字段数组、`context_windows` / `context_limits` 等档位列表，以及字段的 `enum` / `options` 声明；接受正整数和数字字符串，去重排序。
- 单个窗口继续沿用原来的显示。多窗口模型在“模型与渠道”展示完整列表，可选择默认窗口，自动保存。刷新目录保留仍然受支持的选择；档位被上游明确移除时清除旧选择。
- 主 Agent 输入栏的思考按钮旁显示当前窗口的简写；打开按钮，在“上下文窗口”中切换精确值。会话覆盖与渠道默认分开保存，可恢复渠道默认。
- 新会话携带所选窗口；已有会话运行期间可切换，下一次模型请求会重新计算历史整理与请求预算。正在发出的请求保持原状，其它会话不变。重启保留选择，切换到不支持该档位的模型会清除覆盖。
- 一键配置外部工具时投影所选默认窗口；普通保存不触发外部配置写入。DSH、ZCode 等依旧通过已有备份与冲突处理写入。
- LiteLLM 多部署仅使用每个部署明确提供的窗口列表交集，不把不同部署的单值窗口直接合并成可选档位。Copilot 和托管订阅目录保留可读取到的窗口枚举。

只展示目录明确提供的档位，不从模型名猜测，也不把 min/max 范围或输入预留上限编造成窗口选项。所选值用于本体的上下文预算和外部配置投影，不擅自向上游发送未知的 `context_window` 参数。需要专用请求开关的渠道，应按其实际协议单独适配；本次未取得用户所指具体渠道的响应样本，因此不宣称覆盖所有私有字段格式。
