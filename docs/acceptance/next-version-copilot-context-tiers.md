# GitHub Copilot 多上下文预设（待下次打包）

## 修复范围

之前只解析 `context_windows` 等枚举数组；GitHub 实际通过 `billing.token_prices.default` 和 `long_context` 提供预设。旧的 `2025-10-01` 接口版本还会隐藏这部分信息，导致模型始终显示单一窗口。

- 目录获取与网关请求统一使用 `2026-06-01` 合约。
- 解析标准／长上下文预设，兼容 `context_max` 与新版 `max_prompt_tokens` 字段。免费长上下文没有独立价格项时，按官方客户端规则使用公布的完整输入预算。
- 区分输入预算、模型总窗口和最大输出，不把三个不同的上限错误地当成三个可选预设。
- “刷新模型”绕过旧目录缓存；刷新失败保留原缓存，成功后更新模型列表并保留仍有效的选择。
- 模型配置和 Agent 思考／上下文菜单显示“标准档”“长上下文”；选择自动保存，进入 Agent 的实际预算。保存渠道选择不擅自重写外部工具。
- 同时保留 GitHub 公布的最大输出，不再把已返回的输出上限丢弃。

## 实机目录证据

2026-10-19 仅通过已授权账号读取官方模型目录，没有发送生成请求。相同账号、相同官方 API 主机下：

- 旧版本返回 51 个模型，示例 GPT-6.1 Sol 仅返回 272,000 输入／400,000 总窗口。
- 新版本仍返回 51 个模型，GPT-6.1 Sol 公布标准输入预算 272,000、长输入预算 922,000、总窗口 1,050,000、最大输出 128,000。
- 回归固定样本仅保留公开的模型能力字段，不包含账号标识、认证 Token 或个人配置。

## 手动验收

- [ ] 在模型与渠道中，点击 GitHub Copilot 的“刷新模型”。
- [ ] 对支持多档的模型，确认出现真实的标准档／长上下文选择；无预设的模型不伪造选项。
- [ ] 选择较大档位，刷新和重新进入页面后保持选择。
- [ ] 工作台的思考／上下文菜单能切换会话窗口，恢复默认后跟随模型设置。
- [ ] 外部工具需要点击一键配置后更新；已有手动配置与其他会话保留。
