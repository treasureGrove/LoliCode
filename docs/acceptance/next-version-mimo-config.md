# MiMo 模型可见但配置报错（待下次打包）

## 原因与修复

MiMo 的模型 `limit` 是可选字段，但一旦提供，必须同时包含 `context` 和 `output`。部分渠道目录只声明其中一个；旧适配器把不完整的对象写入 MiMo，导致配置校验失败。

现在仅在上下文窗口和最大输出均已知时写入 `limit`；缺少任一值时，交给 MiMo 自身的模型目录与默认策略处理，不猜测上游数值。LoliCode 内保存的渠道能力信息保留。

旧版已经写入的托管配置，重新点击一键配置即可修正；继续保留原文件备份、无关设置和同名模型的防覆盖检查。用户自行修改过的托管提供商不会被强行覆盖。

## 已验证

- 外部应用配置适配器 21 项测试通过，包括完整上限、仅上下文、仅输出、均未知，以及旧配置修复、备份、重复配置与手动修改保护。
- 本机 43 个托管模型中有 29 处不完整 `limit`；核对托管指纹后完成修复，原配置及托管记录已备份，记录指纹同步更新。
- 修复后的整个 LoliCode 提供商通过官方公开的 Provider JSON Schema 校验，相关错误从 29 个降至 0。
