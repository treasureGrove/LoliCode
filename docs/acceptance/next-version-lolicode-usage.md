# 下一版：LoliCode 自身用量归属修复

状态：开发分支修复，尚未打包发布；本次没有改动真实账单库。新版本运行用量同步后生效。

## 问题与行为

- 旧版主 Agent 走共享网关，已经记录的 Token 与费用归到 `channel-gateway`，筛选“LoliCode”时看不到。本机只读核对发现 564 笔可以用原生会话请求记录唯一匹配的历史请求；这不是 564 笔新增消费。
- 新增历史归属修复，接入启动 / 后台 / 手动“同步用量”的统一扫描流程。仅在本地原生会话标识、完成时间、请求耗时、输入 / 输出 / 缓存计数严格匹配且两侧均唯一时，把现有请求归回 LoliCode，并关联真实会话。
- 不新增账单，不改请求 ID、模型、渠道、Token、费用或日期。因此全局请求数与总费用不变，LoliCode 分类增加、原网关分类减少，按渠道仍能查看原来的消费。
- 缺少缓存写入计数时不补造零值，使用账单原有缓存写入与总输入交叉核对。计量不完整、时间不可靠、两个请求相互冲突、已由其他导入器认领、或明细已归档无法核对时，保留原归属，不猜测、不补估消费。
- 通过持久去重记录与文件游标保证重复同步、重启、修改文件触发重读，以及明细归档后均不重复记账。最近一分钟的记录稍后再处理，避免与异步账单写入竞争。
- 当前源码的主 Agent、标题与历史整理请求使用专属 LoliCode 网关入口。新增端到端验证覆盖流式 Chat、Anthropic 和 Responses 渠道，确认都能归属 LoliCode、按渠道聚合，并只计一次费用。

会话输入栏统计只覆盖会话主执行请求；全局 LoliCode 用量还可以包含标题生成、历史整理等辅助请求，两者不一定相等。旧版辅助请求没有可靠对应记录时仍留在共享网关分类。
