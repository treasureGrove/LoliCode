# Loli 秘书

工作台左侧的 **Loli 秘书** 位于 **新对话** 下方。每个项目保留一个秘书主会话；再次点击会回到已有会话。首次进入时沿用当前选择的模型、权限、思考强度和上下文设置，已有秘书会话保留自己的设置。

桌宠看板娘的工具栏也提供秘书快捷入口。她读取真实的秘书和工作任务状态，显示正在工作、需要授权／回答或新结果；点击待办会进入对应工作会话。跨页面可用，切换前沿用已有未保存内容保护。摸头、投喂、拖动、停靠和休息沿用原有交互；休息时不展示工作提示，隐藏看板娘不会取消任务。

直接在秘书对话里说你想完成什么。秘书会拆解工作、拟定任务标题和目标，并根据任务之间的关系安排串行或并行。后台工作会话使用同一套模型通道、工具、技能、记忆、权限、问答、取消和用量系统。秘书接收补充要求、跟进任务状态，并汇总工作结果。

## 查看和控制工作

要直接交办一项工作，点击秘书主对话顶部的 **交办任务**，填写任务名称和工作要求。默认在当前项目目录执行，也可以为能从已提交版本开始的 Git 任务选择独立工作树。提交后在 **工作任务** 中跟进。

对话顶部会按实际派发关系列出 **总秘书** 和已有的子代理，并显示任务状态。点击名称可以直接切换对话，**工作任务** 收起时也能使用。

展开秘书主对话顶部的 **工作任务**，可以查看实际执行状态、结果和失败原因，也可以发送跟进、取消任务或打开工作对话。打开工作对话后可返回秘书，主对话草稿保留。

工作会话需要权限或回答问题时，任务区显示待办，打开对应会话后使用现有权限卡片、问题卡片处理。秘书不能代替用户批准。完成、失败和待用户处理的状态会自动回报秘书；回报本身没有发起新任务、继续执行或取消其他任务的权限。

从桌面对话分派的工作任务可以在输入框设置中调整执行权限。更改仅对该任务的后续工具检查生效，已经弹出的请求仍需处理。按规则自动派工和手机后台任务使用逐次确认。

桌面秘书可以按用户要求在侧栏打开项目文件，也可以直接运行一次性的检查命令。命令沿用会话权限。HTML 预览会过滤脚本，依赖 JavaScript 或 WebGL 的页面需要在浏览器中运行。打开独立工作对话后，可从该任务的工作树手动预览文件。

秘书可以直接生成或编辑项目文件。在逐次确认和 Auto Mode 中，本机编辑会先显示差异，并等待一次性批准。完整权限下，文件工具和命令按当前会话权限直接执行。写入前若文件已变化，应用会拒绝这次写入，需要按新内容重新生成差异。补丁以单文件为单位。

桌面秘书和普通 Agent 可以用 `web_fetch` 读取公开 HTTPS 网页的正文、纯文本或 JSON。抓取不加载脚本、登录状态和浏览器 Cookie。启动 LoliCode 时提供 `LOLICODE_BRAVE_SEARCH_API_KEY` 可启用 `web_search`，搜索词会发送给 Brave Search。网页访问沿用当前会话的授权策略，结果按外部参考资料处理。

### 在浏览器中验证本地页面

需要启动本地开发服务时，秘书可以调用 `manage_process` 的 start 操作，指定启动命令和服务端口。工具等到端口就绪才返回进程 ID，之后可以用 logs 查看日志，用 stop 停止。短命令工具 `run_command` 在超时后回收进程树，并保留已产生的输出。

本地开发服务就绪后，可以让桌面秘书打开回环地址，查看页面信息、点击控件、拖拽画布、滚动并截图。侧栏显示隔离浏览器的实时画面，页面交互由浏览器工具执行。折叠侧栏会保留预览，点预览右上角的 × 可以关闭浏览器。截图以原始 PNG 进入聊天，能否识别由当前上游模型决定。用完可停止由秘书启动的服务。

### 秘书如何安排串行和并行

依赖前一步结果的工作，由同一个任务按顺序完成。需要未提交文件或项目应用工具的任务在当前目录执行，同项目依次运行。能从已提交 `HEAD` 独立开始的 Git 任务可在各自的工作树并行执行。同项目最多同时运行三个独立工作树任务和一个当前目录任务。需要授权或回答的任务保留其槽位。任务区和看板娘会区分正在执行与排队。

独立任务的详情显示基线、分支和目录。工作树的文件工具和命令使用独立目录，沿用分派时的模型、权限、技能和项目记忆。绑定当前项目的应用工具和 MCP 适合用当前目录模式运行。任务完成、取消或中断后保留工作树和分支，供你审阅成果。

每次工作任务运行都有独立的命令临时目录。原生命令通过 `LOLICODE_AGENT_SCRATCH`、`TMPDIR`、`TMP` 和 `TEMP` 获得目录路径，可用于解包和存放调试文件。运行正常退出或受控取消后，程序清理该目录。需要交付或后续预览的文件应写入任务目录。项目里已有的截图、解包文件和工作树由用户保留审阅。

秘书可以把其他任务的发现作为便签转给仍在工作或排队的任务。便签会出现在工作会话中，继续执行和更改任务要求则使用明确的用户跟进。

## 接收和回复 GitHub 工作

在秘书顶部打开 **GitHub**，输入 `owner/repo` 或仓库地址。连接使用本机已登录的 GitHub CLI。可以手动同步，也可以打开 **自动收件**，由本体在桌面运行期间定期读取 Issue、PR、评论、行内 Review 和 Actions 状态。

选择一个条目，写明 **交办要求**，再点击 **交办此条目**。外部正文会作为参考，任务在当前项目的独立工作树中执行。已交办条目可以直接打开工作会话，任务详情也保留原帖链接。

任务完成后，在原条目展开 **准备回报**，编辑正文并确认发送账号，点击 **发送到 GitHub**。如果结果待确认，重试会用保存的原文核对原线程。回报成功后可打开 GitHub 上的回复。

## 按规则自动派工

在 GitHub 面板展开 **自动派工**。功能默认关闭。启用自动收件后，可以为当前仓库配置允许发起任务的 GitHub 账号、条目类型、触发词和任务要求。例如触发词为 `typo` 时，允许的账号可在新条目的第一行写 `/loli typo`。触发后的工作内容由保存的任务要求决定，GitHub 正文作为参考。首轮同步建立基线，后续新条目才参与匹配。可以在同一面板查看命中、派发和失败记录。

规则任务在独立工作树中运行，文件修改需要一次性授权。需要执行终端命令或操作桌面应用时，请另行明确交办。关闭自动派工会停止接收新的规则任务，已派发任务在工作任务面板管理。

## 发布草稿 PR

在已完成的独立工作树任务中准备草稿 PR。当前项目的 `origin` 需要指向秘书绑定的仓库，目标使用该仓库的默认分支。如果提示基线不可用，先同步默认分支。核对 GitHub 账号、目标和变更后，编辑标题及说明，再点击发布。发布会把审阅过的任务快照推送到任务分支，并创建草稿 PR。结果待确认时，使用原草稿重试，秘书会先核对远端分支和已有 PR。

## 保存和恢复

任务关系、执行记录和待投递报告保存在本体会话中。页面切换不会取消工作。关闭桌面应用后停止执行；重开时保留记录，未完成的运行显示为中断，需要明确跟进后继续，不自动重放之前的工具。

运行中若模型流在已有输出后停滞或断开，Agent 会带着已完成的工具记录续跑一次。若仍中断，或任务被取消，任务摘要会列出本轮已确认的工具调用和保留的部分答复。

分派和跟进使用稳定请求编号去重。任务状态依据原生执行回执、权限和问答状态生成；完成任务仍可在明确跟进后继续。状态报告通过持久队列回到秘书，主会话忙时排队等待。

跨正式版和开发版的手动会话同步暂时跳过秘书及其工作会话，并给出原因，防止单独复制会话破坏任务关系。普通会话继续使用原有同步。

## 实现和验证

协调逻辑位于 `crates/lolicode-agent/src/native/secretary.rs`，直接使用 `NativeEngine`。桌面命令位于 `src-tauri/src/commands/agent_secretary.rs`，任务界面位于 `src/features/agent/AgentSecretaryTasks.tsx`。

这是按当前原生架构编写的实现，参考 DeepSeek Superagent 的协调者、工作任务、GitHub 来源、上下文便签和持久投递机制。来源、差异与许可证见 [DeepSeek Superagent 原生适配记录](../architecture/deepseek-superagent-adaptation.md)。

公开接口验收位于 `crates/lolicode-agent/tests/secretary_workflow.rs`，以本机确定性 SSE 响应器驱动生产执行链，实际验证任务分派、临时项目文件写入、自动汇总和重开不重复执行。该测试不调用外部模型，不代表已经验证真实模型的分派质量。
