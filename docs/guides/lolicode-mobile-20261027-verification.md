# 手机同步与 1 MiB 消息验收

日期：2026-10-27。本文记录 Windows 原生 4.1.3 和 Android alpha.4 调试构建的验收。正式安装包、实际升级和公开分发结果另见 [v1.0.3 交付记录](lolicode-v1.0.3-delivery.md)。

## 大小与传输

单条逻辑消息的完整 UTF-8 JSON 上限为 1,048,576 字节，包括 RPC 信封。两端均验证恰好 1 MiB 可以收发，多一字节明确拒绝。超过 5000 字节的对象先压缩，再经原有小帧加密传输；长度、顺序、解压边界和 SHA-256 全部通过后才交付完整对象。

模型目录默认完整返回。已移除手机端原有的 256 个模型、32 页和 2048 个结构节点限制，目录仍受完整消息大小与 20,000 个条目的保护。显式分页继续兼容旧客户端。

服务器每帧 8192 字节、全局 8 KiB/s、账户 2 KiB/s、月度 2 GiB 的限制均保留。服务器不解压正文；文本模式的媒体、方法和审批限制保持有效。票据续期只接受服务器对同一账户、设备、角色和房间的匹配确认，不改变密钥、epoch 或已用额度。

## 自动化验证

- Windows 手机模块：67 项通过，1 项需要人工原生互通的测试未执行。
- Android JVM：95 项通过，lint 无错误；调试应用和仪器 APK 构建、更新安装成功。
- 账户中转服务：70 项通过，部署工具的 26 项 Linux 测试通过。
- 两端使用独立 Python 生成的 zlib 固定向量，覆盖中文、跨片组装、恰好 1 MiB、额外一字节、乱序、重复、混片、取消、超时、损坏、解压炸弹和尾随数据。
- 实际本地 WebSocket 与加密测试覆盖大消息的原子交付、部分上传取消、连接内续期及临时握手冲突恢复。

## 真实账号与手机

使用小米 8 Lite（Android 10）和正常桌面应用、实际账户登录及现有授权。手机保持用户选择的另一条 Wi-Fi，电脑保持原网络。实际业务传输为加密文本通道；本轮不将其记为跨网 P2P 成功。

完整模型目录的真实验收通过：45 个模型全部加载，原有 20 个会话分 4 页完整同步。随后先比对一条已有会话的完整文字，再独立创建一个验收会话，发送一次最小真实模型提问。两端观察到同一条 65 字节的模型回复；没有调用工具或改写项目文件。

首轮主动重连未恢复，保留了失败记录，没有重新创建会话或重发提问。后续发现电脑发送队列的确定性错误：未确认的完成通知可以越过初始授权确认。回归测试先复现错误顺序，再验证修复；手机的严格授权校验没有放宽。另用本地真实 WebSocket 验证并修复了旧连接关闭尚未完成时的临时角色冲突重试。

修复后的真实只读恢复验收通过，用时 97.608 秒：21 个会话、45 个模型完整同步，已有验收回复在主动重连前后均经过重新 attach/get，比对完整内容哈希一致。此次恢复没有创建会话、发送提问或重试修改操作。

正文、密码、令牌和密钥不进入验收输出。只有计数、固定阶段、字节数及完整性摘要用于比较。正式旧客户端和其登录数据未替换为调试包。

## 真实界面

真实界面完整验收通过，用时 157.864 秒，外部 600 秒上限未触发。测试复用实际 `MainActivity` 的同一个 ViewModel，经正常应用启动入口打开界面，随后执行真实 Compose 点击：设备选择与刷新、21 个会话的 4 页目录、已有回复的实际文字显示及哈希、界面重新连接、显式刷新任务后的完整回复校验、45 个模型的菜单选择。模型选择确实发生改变，没有创建会话或发送提问；最后正常关闭 Activity 并确认销毁。

前几轮仪器启动等待和较短诊断上限未完成的记录均保留，没有回填为通过。最终运行明确记录界面由一次普通 ADB 应用启动触发，不将测试上下文的启动请求冒称成功；没有修改 MIUI 权限、解锁或构造第二个 ViewModel。

## 未扩展的验收范围

实际生产链路没有灌入 1 MiB 压力负载；大小边界由本地完整编解码和加密传输测试验证。本文也不将上述结果扩展为跨网 P2P、锁屏推送、Windows 焦点或锁屏行为、所有工具审批流程和正式安装器升级的实测结果。
