# 酒馆本地陪伴模型

用户选择：硅基女友 v2 9B，`sbg-v2-9b.imat-Q4_K_M.gguf`，固定 16,384 token 上下文。

## 使用

打开「酒馆 → 本地陪伴模型」，展开设置后选择「一键配置并启用」。模型设置默认收起为状态栏；下载中仍显示进度，收起不会暂停下载。展开的设置区域可内部滚动，给聊天入口与输入框留出空间。首次从 Hugging Face 和 llama.cpp 官方发布下载约 6.36 GB，支持暂停、继续与 SHA-256 校验。安装完成后直接选角色聊天，无需 API 密钥。

当前支持 Windows x64 + NVIDIA 显卡，至少约 6 GB 显存，建议 16 GB 系统内存、安装时预留 16 GB 磁盘空间。驱动必须能够运行所固定的 CUDA 13.4 运行时。6 GB 显卡默认把 8 层 FFN 放到 CPU/系统内存，Q8 KV、Flash Attention、单会话槽位、非思考模式；显存较充足的显卡使用全 GPU。运行时加载失败会显示日志位置，保留已下载文件供重试。

「释放显存」停止本应用启动的模型进程，保留安装与本地模型选择，下次发送自动启动。「使用渠道模型」显式切换回已有渠道。本地生成失败或模型文件缺失不会自动向云端发送对话。

角色、世界书、当前输入优先保留。按模型真实模板与 tokenizer 计算上下文，预留 1,024 token 输出和 256 token 余量，超过窗口时从最早的对话开始省略。角色与世界书本身超过窗口会报错，不静默截断当前输入。当前还没有自动摘要或跨故事长期记忆。聊天记录仍由原有酒馆存储保存，计算时省略的历史不会从故事中删除。

文件位于当前应用配置目录的 `tavern/local-models/sbg-v2-9b/`；默认是 `%USERPROFILE%\.tai-switch\tavern\local-models\sbg-v2-9b\`。其中 `installation.json` 保存启用状态和运行时文件摘要，`server.log` 是启动诊断。服务只监听随机的本机回环端口，并使用每次启动生成的访问令牌。退出或重启应用会清理本应用拥有的模型进程。

## 固定来源

- [模型仓库](https://huggingface.co/RX5950XT/silicon-based-girlfriend-v2-GGUF)，revision `6a1bb825afbc8cf3363c4a201f231f378cfc0123`，文件 `sbg-v2-9b.imat-Q4_K_M.gguf`，5,780,091,104 bytes；SHA-256 `f3db124770a54961bb703929f584f8616f3cbc181c952dce4293d2ad1d103034`。
- [llama.cpp b11729 官方发布](https://github.com/ggml-org/llama.cpp/releases/tag/b11729)，`llama-b11729-bin-win-cuda-13.4-x64.zip`，155,124,217 bytes；SHA-256 `ea675c73c7436c73654ca3faf45fc5a667966db7df9490a9455fb3f833b3574a`。
- 同一发布的 `cudart-llama-bin-win-cuda-13.4-x64.zip`，423,535,356 bytes；SHA-256 `738f8c251ac22b70c3ae6f83a10cf222725df0395246a2cf58f32bdb85fbe668`。

固定采样参数：temperature 0.85、top_p 0.9、top_k 40、min_p 0、repeat_penalty 1、presence_penalty 1.5；使用 DRY 防复读（multiplier 0.8、base 1.75、allowed_length 4、最近 2,048 token），降低连续复制旧台词的概率。使用 GGUF 内的原生模板并关闭 thinking。角色卡的后置约束合并入初始 system 消息，以兼容 Qwen3.5 模板。

酒馆共用的接话约定适用于本地和渠道模型：通过角色的措辞、偏好和判断体现个性，日常短聊通常一到三句说到点上就停，话题需要时再展开。动作和提问按情境出现，用户已经明确的选择、拒绝与偏好承接到后续回复。角色卡或用户明确的文风、语言和叙述视角要求优先。

开场设定是故事起点，后续地点、物品状态与关系以实际对话的新进展为准。语气示例只在前三个成功的用户与角色回合提供，此后让真实对话接续口吻；示例事件不属于当前故事。失败的发送不进入生成上下文，也不触发世界书条目。历史保留最近最多 60 条有效消息，截断时从用户消息开始，避免孤立的旧回复。角色字段、开场白和世界书中的 `{{char}}`、`{{user}}` 会展开为角色名和「用户」；未知宏保持原样。

八张内置卡提供更多样的日常接话示例。已经添加的内置卡只更新仍与旧默认内容完全相同的字段和世界书正文；用户改过的字段、导入卡、头像与未知扩展保持原样。读取时在内存中应用更新，随之后的正常保存持久化，已有故事里的开场白和历史消息不会重写。当前没有自动摘要或跨故事长期记忆；这些调整也不能保证小模型完全摆脱语义层面的套路。

## 验证与复现

自动检查覆盖断点下载、Range 响应校验、SHA 不匹配时保留已有文件、ZIP 路径限制、上下文整理、显式模型来源切换，以及界面安装后刷新模型目录并发送本地请求。

2026-10-23 对共用提示与内置卡做了本地同参数对照，使用两个角色、每个角色四轮的独立合成故事，未读取或改写用户故事。最终版本另用一个随机种子复核：sillyLoli 的部分短聊与转场衔接较好，但芙宁娜仍有密集括号动作、舞台隐喻、违背安静等船偏好及补写关系事实的问题。动作标记变少不能当作自然度改善的证据；这组小样本不证明整体质量提升，也不覆盖渠道模型。

可用已下载的官方文件执行真实安装验收（此命令明确会配置当前用户的本地模型；聊天使用临时内存数据库）：

```powershell
cargo run --manifest-path src-tauri/Cargo.toml --features test-hooks --example tavern_local_acceptance -- <GGUF路径> <两个官方ZIP所在目录> <验收JSON输出路径>
```

验收使用实际安装器、校验器、运行时与酒馆服务，检查三轮中文陪伴对话、角色后置约束、世界书、消息保存，以及释放显存后的自动启动。开发配置单独优化 SHA-256 依赖，避免未优化的调试代码拖慢大文件校验。

资源测试脚本为 `scripts/tests/tavern-companion-benchmark.py`。2026-10-20 在 RTX 5060 Ti 16 GB、Ultra 7 265KF 上验证默认的 16K、CPU FFN 8 层配置：两个 14,080 token 冷输入请求均完成，结构化事实回忆 9/9；模型进程峰值专用显存 4,696 MiB（4.59 GiB）、共享 GPU 内存 78 MiB、RSS 5,857 MiB（5.72 GiB）、private commit 6,147 MiB，生成约 29–32 token/s。这些是单独模型进程的资源，不含应用、操作系统与其他程序；物理 6 GB 显卡仍需另行确认，中文角色扮演样例也不能代替成人内容专项测评。
