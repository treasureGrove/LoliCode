# LoliCode 产品方向

更新：2026-10-15

定位：**简单易用，扩展性强的二次元美少女多功能 Agent。**

本文件记录已对齐的产品方向。它描述愿景与产品边界，不将路线图写成已交付功能。当前实现与发行状态以 README 和交付记录为准。

## 产品的主角

LoliCode 面向喜欢二次元的用户：一位有鲜明人设、萌系美少女与萝莉风形象的 Agent，既能交流陪伴，也能完成编程、资料处理、创作和工具操作。视觉、语言、动效、声音和互动共同形成产品体验，不能只给通用工具管理器换一张背景图。

“极致二次元”是审美追求；简单易用和真实完成工作同样属于产品核心。关键操作、错误、任务进度和结果必须清晰，角色动作不能遮挡内容或伪造成功。支持安静工作、减少动效和按需隐藏 Pet，让不同使用场景都可持续使用。

## 一个主 Agent，多种能力与表现

主 Agent 对话入口始终只有一个，直接可用，不通过应用中心安装。允许切换历史会话、项目和任务；幕后可以委派子任务，但不会为每个工具或应用创建一套主聊天窗口。

主界面角色、桌面 Pet、语音和未来角色表现共享同一 Agent 身份、对话与任务服务。它们是不同的呈现和输入输出方式，不各自维护互相冲突的独立大脑。

主 Agent 可持续获得其他 Agent 的成熟能力。DSH、OpenCode、ZCode 是工具、上下文、模型调用、任务与交互的参考来源；后续候选不限于这几个项目。以具体功能、组件、协议和可替换服务接入，不承诺执行所有上游插件或打包全部上游程序。

## 简单易用

首次使用先完成少量必要配置：连接模型或账户、选择工作位置，随后直接与主 Agent 对话。优先识别已有配置并使用推荐默认值，缺少什么就说明什么；失败可以原地修复，不让用户从头填写。

日常界面聚焦对话、当前任务、角色互动与结果预览。模型原生参数、工具范围、Skills、MCP、记忆策略、路由和诊断放入清晰的高级入口，完整保留，需要时再探索。

配置基座延续 CC Switch 的既有实现和成熟流程，减少手动编辑配置文件。账户凭据统一保存，应用只引用已有账户，不重复索取和复制密钥。

## 扩展性强

产品区分五种扩展对象：业务应用、Agent 工具、Skills/连接器、后台能力提供者、角色与互动资源。

业务应用有独立工作区和领域数据，例如文档知识库、酒馆、UE 工作台。像飞书、钉钉一样从目录添加到“我的应用”后使用；主 Agent 通过已启用应用的工具操作业务，也能打开对应页面和产物。第一阶段先做内置业务应用，第三方网页、服务与应用接入后置。

记忆、模型、语音等能力提供者通过明确接口接入；不能把每种能力都包装成一个新的聊天应用。角色外观、人设、声音和 Pet 资源可分别扩展，替换它们不清空用户项目、任务或记忆。

新增接入先写清功能、所属模块、数据归属、执行目标、来源和许可，再进入验收清单。扩展接口应保留模型和领域差异，避免为了统一而削减功能。

## 记忆、Pet 与语音

长期记忆是主 Agent 的能力，区分用户偏好、环境与项目经验、知识资料和叙事设定，支持查看、纠正、遗忘和导出。先做可管理的本地持久化，再按需适配外部提供者。角色扮演中的虚构事实不自动写成用户现实资料。

Hermes 的内建持久记忆和外部记忆提供者机制是研究对象。具体采用哪个组件需完成源码、依赖与许可评估，不假定某个“记忆插件”天然独立于 Hermes 即可运行。[持久记忆说明](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)、[记忆提供者接口](https://hermes-agent.nousresearch.com/docs/developer-guide/memory-provider-plugin/)

Pet 展示待机、思考、执行、等待、完成等真实状态，并提供轻量互动与回到主 Agent 的入口。后台任务不依赖 Pet 窗口是否打开。

语音逐步加入输入、合成、流式播报、打断和口型/表情联动。主 Agent 的人格与任务状态统一；停止说话与停止执行明确区分。语音、形象 SDK、模型和素材的许可分别记录。

酒馆提供角色与世界等叙事业务，UE 提供工程资源与编辑器能力；它们扩展主 Agent 的活动范围，各自保留领域规则和数据。

## 迭代原则

第一优先级是主线 Agent 产品与对应交互：用户回答问题、选择方向、查看思考状态、跟踪工具执行，以及取消和恢复。随后接入 UE Box 领域能力与参考开源酒馆实现的酒馆应用，再做第一期验收。只实现当前链路必要的交互 UI；整体二次元前端视觉统一放到后续，不先开展全局换肤和布局重构。

长期记忆、Pet、语音、角色动作与后续应用沿用已确定的接口边界持续迭代。记忆提供者、形象资源和音色等候选先完成评估，再进入明确的交付范围。每阶段写清实际可用能力、失败恢复与后续目标。

当前技术迁移建议为 Electron、现有 React、自有 TypeScript Host/Agent Kernel 和保留 Rust 原生服务；当前默认发行仍是 Tauri 与进程内 Rust Agent。技术选型服务于产品方向，不能把换壳当作产品交付。

先使用可运行底座推进主 Agent、两个应用和验收；目标 Host/桌面壳迁移按功能对等条件安排，不能成为本期业务闭环的前置重构。实施与验收项见[第一期计划](lolicode-phase-one-plan.md)。

涉及方向选择时再与用户对齐；常规实现、兼容处理和验证自主推进。不得将未实现的记忆、Pet、语音或领域应用写成当前已有功能。
