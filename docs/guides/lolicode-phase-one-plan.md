# LoliCode 第一期实施与验收计划

更新：2026-10-15

状态：实施计划，尚未完成验收。

产品原则：简单易用、扩展性强、唯一主 Agent、二次元美少女产品方向。全局前端视觉后续统一处理，本期优先完成 Agent 与对应交互，再接 UE 和酒馆两个内置应用。

## 1. 主线 Agent 与交互

先核查并完善现有实现，不通过增加另一套主聊天窗口解决问题。

- 提问：模型/工具问题有明确问题 ID、所属会话和当前等待状态。
- 回答：选项、自由输入、必要的多选与跳过语义按题型处理；发送中不重复提交。
- 方向选择：展示选项的含义与差异，推荐只是提示，未提交不算选择。
- 思考：按后端真实事件显示状态；只展示模型实际提供的可显示推理内容，没有内容时不编造推理文本。
- 执行：工具开始、进度、完成和失败分别展示，保留产物及具体变更。
- 控制：等待用户、权限或工具时仍可取消；停止播报与取消任务未来也分别控制。
- 恢复：切换会话、刷新、断线与重启后能恢复当前状态，不重复回答或自动重放工具副作用。
- 模型：保留当前支持的原生参数、推理和内容块，明确不支持的协议或能力，不静默降级。

每项记录实际行为、复现步骤、源事件、前后端合同和测试证据；不能用静态组件或模拟成功替代执行链验证。

## 2. 两个内置业务应用

应用像飞书、钉钉的业务应用一样添加到“我的应用”，拥有业务页面和数据，向同一主 Agent 暴露工具。主 Agent 不属于待添加应用。第一期先做内置接入，第三方应用后置。

### UE 工作台

研究 UE Box 与 UnrealAgentLink，固定源码及实际支持的 UE/系统版本，整理选定领域工具与依赖清单。

第一条闭环包含选择工程、发现/连接编辑器、主 Agent 选择并调用工具、收到真实结果，以及对应的保存/编译/读回验证。添加后的能力发现、参数、失败、权限、锁、取消和断线恢复单独验收。工程资源与编辑器操作保留为同一领域的两个能力集合。

未完成的工具如实列为未验收，不能以连接成功代替全部 UE 功能完成。真实编辑器不可用时保留阻塞项，不用夹具宣布编辑器验收通过。

### 酒馆

以 SillyTavern 为主参考，RisuAI 补充参考角色表现和长对话记忆；具体提交、源码入口与边界见[酒馆主参考选择](lolicode-tavern-reference.md)。研究角色卡、世界书、对话、采样与工具扩展，先确认具体代码与许可。可以兼容格式并自主实现，不能因进行了适配就忽略原许可。

第一条闭环包含角色导入、世界书/上下文组装、沿用模型渠道生成、保存与恢复，以及主 Agent 通过明确工具操作酒馆业务。剧情对话是酒馆领域内容，不另造一个通用主 Agent 聊天入口。

格式字段、未知字段保留、触发规则、提示顺序、重生成、分支、采样与后续多媒体按功能清单逐项扩展；不承诺任意现有 DOM 插件兼容。

## 3. 第一期验收门槛

验收必须同时报告通过、失败、未验证和未实现，证据对应具体提交与环境。

1. 新用户可完成必要模型配置并在唯一主 Agent 中完成真实任务。
2. 提问、回答与方向选择的发送、失败重试、重复点击和恢复行为可验证。
3. 思考和工具状态与后端一致，结束后不会残留假的运行状态。
4. 工具输出、代码差异、文件或业务产物能与实际执行对应。
5. 取消和中断恢复不重复执行已有副作用。
6. 内置应用的添加、配置、打开与移除不创建额外主 Agent，不误删业务数据。
7. UE 链路在记录的真实编辑器环境通过，未覆盖工具明确列出。
8. 酒馆的导入、上下文、生成与保存恢复通过，未知格式字段不丢失。
9. 新增源码、依赖与资源均有来源与许可记录。
10. 回归当前已有模型、账户、配置、历史与打包流程；没有验证的操作系统不宣布通过。

全面二次元视觉重构、Pet、完整语音与第三方应用平台属于后续迭代。它们的架构位置已保留，不能用占位入口计入本期完成率。长期记忆等新增 Agent 能力采用独立交付项记录，不在未完成源码评估时假定已经集成。

## 4. 工作方式

按“问题与行为复现 → 最小完整修改 → 对应验证 → 记录结果”迭代。常规实现自主处理，涉及产品方向、功能范围或许可路线的实质取舍再向用户提问。

自动验证默认采用隔离项目与本机夹具；真实 UE 环境使用专门验证工程，并记录引擎、插件与工具版本。不能用模拟结果代替真实环境验收。
