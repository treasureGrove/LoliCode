# 工作流、自动化任务与插件

自动化由 LoliCode 桌面调度器保存和投递，实际任务在 Harness 对话中运行。

## 工作流

- 在「工作流与自动化 → 工作流」直接新建 Markdown 工作流，使用 `description` YAML frontmatter 和任务步骤。也可以让主 Agent 写入项目的 `.zcode/workflows/名称.md`；该位置保留已有保存格式的兼容性。
- 参数支持 string、number、boolean、json、必填及默认值。运行前校验参数，非法输入不会发模型请求。
- 每次运行绑定持久化记录、固定会话和请求编号。连接回复丢失后按原参数重试，不会多建一次任务；可检查上次运行并打开原会话。
- 会话自动改标题不会丢失工作流运行记录。停止、失败和完成由实际命令收据区分。
- 当前执行的是由主 Agent 遵循的保存步骤，不提供 ZCode 专用 JavaScript 工作流 SDK 或任意脚本图执行器。

## 自动化任务

- 从左侧「自动化」进入。「新建」在新对话中预填需求，发送并确认配置后才保存。也可从相邻菜单选择「手动创建」，直接保存规则。
- 定时任务支持仅一次、每小时、每天、每周，按本机时区配置。默认新建一条对话供后续复用，也可选择已有对话或每次新建。应用需要保持开启才能投递。
- 「规则」管理运行计划和投递目标。「投递记录」显示发送状态、当次指令和可用的会话入口。选择已有对话时，投递要求该对话空闲，后台运行使用逐次确认。
- 已保存的「电脑闲置时运行」规则仍可使用。系统检查实际键鼠闲置时间，并等待 Agent 空闲后触发。
- Windows 使用 GetLastInputInfo；macOS 读取 IOHIDSystem。Linux 的 X11 可使用 xprintidle，缺少检测能力或 Wayland 环境会明确显示未支持，保留任务等待，不以窗口失焦冒充闲置。
- 支持修改任务、立即运行、暂停计划、停止正在运行的记录、打开原会话和删除。暂停计划不等于停止已启动的运行；删除前需先停止活动任务。
- 同一任务不会重叠领取；一次性任务仅领取一次。应用关闭或休眠错过超过两分钟的定时触发会记录为「已跳过」，不会醒来后密集补跑。
- 权限设置沿用本体 Agent，等待权限或问题时可打开会话处理。不会为后台运行擅自升权。
- 重启只恢复运行记录；未完整结束的任务显示失败并保留会话，不依据“已有文字”宣称成功。

## 插件

从左侧「插件」管理随 Harness 打包的官方插件。持久终端可在多次工具调用间保留命令环境，Ralph 支持由用户发起的迭代任务。切换后在下一次适用的运行启动时加载。

旧 CLI 技能包和本地配置在「兼容扩展」查看。已有 CLI 技能仍可启用、停用和卸载，执行权限沿用当前 Agent 设置。


### 兼容扩展来源与许可

- 旧适配器参考本仓库固定的 `third-party/zcode-runtime/upstream`。CLI 安装器由 LoliCode 用 Rust 实现，已有包由兼容扩展继续管理。
- CLI 目录来源：<https://cdn-zcode.z.ai/zcode/official-plugin/marketplace.json>。`cli-marketplace.json` 保存 2026-10-17 的八项元数据与原始包校验值；刷新通过同一官方地址进行。
- CLI 插件正文未作为本轮源码打包或重新发布；用户安装时从原发布服务获取，原始包声明继续适用。接入或改写并不自动免除原许可要求。
- 实测 GitHub CLI 包的 `UPSTREAM.md` 写明其原上游声称 MIT、但缺少 LICENSE 的发布条件仍待确认。保留该声明，不把市场条目一律标为 MIT。若未来随安装包分发完整 CLI 插件，需要逐项审查各自许可与来源。

## 验收边界

测试采用临时目录和本机 HTTP 回环模型：验证真实 NativeEngine 收据、停止、失败、重启、重发幂等；验证 CLI 技能按需注入、参考资料读取、权限等待、一次批准后执行沙盒脚本及输出。另显式从官方 CDN 下载八个真实插件并校验、安装、解析和注册；没有改动用户的全局 CLI 配置或账户登录状态。

真实第三方 SaaS 的写入、付费调用以及用户账户登录未作为自动测试执行。macOS/Linux 的系统闲置分支仍需在对应系统验收。
