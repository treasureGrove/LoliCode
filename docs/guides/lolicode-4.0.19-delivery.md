# LoliCode 4.0.19 安装修复

修复用户在首次安装与重装时遇到的 `Temp/nsh*.tmp/agent/extensions/LICENSE` 写入失败。4.0.18 的升级检查 hook 改变了 NSIS 的全局输出目录；Tauri 随后按相对路径提取主程序与资源，错误地写入临时目录，而目录只在用户选定的安装位置创建。

现在把检查脚本按绝对目标提取到 `$PLUGINSDIR`，不再改变 `$OUTDIR`。保留许可文件、原有进程路径检查和用户数据处理。4.0.18 已暂时撤下默认更新推荐，网站恢复此前已验证的 4.0.16 更新清单，等待修正版公开。

侧栏看板娘改为直接内嵌 PNG 数据，保持原形象，不依赖单独的图片请求或远程图床。其它界面装饰仍由应用本地前端资源提供。模型调用、用户内容中的外部链接及更新检查仍可能需要联网。

## 安装验收

- 先运行真实旧 hook 的隔离回归，首次安装输出目录断言失败，退出码 73，复现缺陷。
- 修正后运行实际编译的 NSIS fixture，首次安装和重复安装均成功，包含中文与空格的路径；主程序哨兵、根 LICENSE 和嵌套 LICENSE 均在指定位置，临时插件目录没有应用资源，用户哨兵保留。
- 既有进程检查和升级保护回归继续通过。最终 4.0.19 的实际 `installer.nsi` 包含的 hook 与已审查源码一致；从它提取全部 115 个真实文件（含 5 份 LICENSE），首次及重复解压逐文件 SHA256 均通过。解压后的实际主程序离线 Agent 自检成功，付费请求为 0，未读取用户配置。

## 看板娘验收

真实 Vite 生产转换输出 `data:image/png;base64`，逐字节还原与原图一致。完整生产构建的浏览器实测解码为 1214×1295；停止本机预览服务器后，通过界面隐藏／恢复重新挂载，图片仍完整显示，无独立图片请求。CSP 维持原有 `data:` 许可，未放宽安全范围；其它三类装饰样式使用本地相对资源，没有远程图片 URL。

4.0.18 的图片在本机生产预览正常，未复现用户 WebView 的确切失败机制；19 通过将原 PNG 内嵌，消除这张图运行时单独路径解析与获取的故障面，而不是未经验证地声称原问题由带宽或 CSP 导致。本机证据在 `release/mascot-4.0.19-proof/`。

这些测试不注册产品、不创建快捷方式、不运行真实卸载器或 WebView 安装、不覆盖用户现有安装和账户数据；不等同于另一台实体电脑的完整安装验收。
