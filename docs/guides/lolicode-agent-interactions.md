# Agent 长任务、交互与模型能力

更新：2026-10-15。本文记录本体 Rust Agent 的行为；UE 和酒馆业务应用仍在第一期后续范围内。

## 长任务与上下文

工具执行不再按 24 或 32 轮强制结束。任务持续到模型完成、用户取消或真实错误；32 轮不是新的默认上限。权限审批、项目边界、单次工具超时等规则仍按原合同执行。

有真实上下文元数据时，核心在完整工具批次之间检查请求预算，计入系统提示、工具定义、已有摘要和消息。当前采用保守的 UTF-8 字节估算，并预留余量，不将其显示成精确的供应商 token 用量。接近预算时显示“正在整理上下文”，通过同一模型生成续接摘要，然后继续任务；长任务可反复整理。

摘要保留任务目标、约束、结果和待办，最新用户输入及近期完整工具调用/结果保持原文。摘要作为带明确说明的用户数据注入，不能提升为系统指令。只有完整、非空、确实缩短请求且成功落盘的摘要才替换活动历史。聊天原文、工具记录和文件差异仍保留在会话快照中。

摘要失败、取消或写入失败不替换旧历史，也不重放工具副作用。未知上下文不会被伪装成 8K；只在网关返回明确的上下文超限错误时尝试整理并重试一次。单个不可拆分的大输入或工具批次仍可能需要更大窗口，届时保留记录并提示实际原因。

## 标题与执行中的配置

首次发言先生成临时标题，任务成功后后台请求简短的会话标题。标题请求不调用工具，有独立超时；失败保留临时标题，下一次成功任务可以重试。手动改名、删除以及较新的会话状态优先于迟到响应。侧栏通过独立的 `titlePending` 和列表 `activity` 合同发现后台任务，无须打开会话才能刷新标题。

输出期间可以修改模型、思考档位、模式和权限，输入区可保留草稿；同一会话仍不能并发发送第二条任务。模型、模式和思考档位在下一次模型请求生效，已发出的 HTTP 请求继续使用原参数。权限变更在下一次工具检查生效，已经弹出的审批仍需明确处理。保存配置期间也可以停止当前任务。

模型选择器按渠道折叠、搜索和选择，使用模型的原始标识，不解析名称猜测渠道。思考、工具详情、变更列表和单文件差异可分别折叠；收起时不挂载大型内容，保留展开与滚动状态。失败会在收起的摘要中提示。

## LiteLLM 能力发现

普通模型目录公开的上下文、输出上限和档位声明优先。对名称为 `LiteLLM`、使用 API Key 和 `openai_chat` 协议的渠道，刷新模型时还会只读查询同一服务的 `/model/info`，按精确的 `model_name` 关联部署信息，再利用明确的上游模型映射补足缺失资料。不会从公司模型别名中删前缀来猜实际模型。

辅助查询不新增未发布的模型，不改变原有模型勾选；没有管理接口权限或请求失败时，普通模型发现仍可使用。请求禁止重定向，设置短超时，缓存按端点和凭据隔离。上游凭据、部署私有参数不会出现在渲染层，也不会为查档位把公司的 Key 发给公共模型目录。

模型明确声明枚举时显示真实档位；明确声明空数组时不伪造选项；缺失声明时允许高级用户填写带“未验证”提示的档位标识。恢复“上游默认”会移除显式档位参数。切换模型时，仅在新模型明确支持旧档位时保留它。

界面分别展示档位来源和参数兼容状态：

- `declared`：中转声明接收 `reasoning_effort`，不等于完成了真实生成验证。
- `unconfirmed`：能确定上游档位，但中转未声明该参数；不能据此认定支持或不支持。
- `mixed`：多条部署的参数声明不同；自动档位只取所有可确认部署的交集，缺失映射时保留未知。

本轮透传兼容 Chat Completions 的 `reasoning_effort`。布尔 `thinking`、token 思考预算、Responses 或原生 Anthropic 的参数不能仅凭一个档位名字自动互换；未声明的中转行为需要按其实际协议继续验证，不能承诺所有模型都已“满血”。默认保留供应商行为，不给所有模型硬塞同一档位或输出上限。

## 参考来源与取舍

本轮参考交互和功能合同，没有启用整套上游程序，也没有增加默认发行依赖。

- [ZCode，固定提交 aac4755](https://github.com/zai-org/ZCode/tree/aac4755666d09fdcd70272fcf063c077a639015f)：工具与模型折叠、后台标题、模型配置。少量精确模型/档位事实取自 [modelRules](https://github.com/zai-org/ZCode/blob/aac4755666d09fdcd70272fcf063c077a639015f/config/provider/zcode-builtin.json)，来源和 Apache-2.0 声明写在 `litellm_capabilities.rs`，既有许可证及 NOTICE 保留于 `third-party/zcode-runtime/upstream`。不是根据所有同名模型推导通用档位。
- [DeepSeek Harness，固定提交 5719020](https://github.com/deepseek-ai/deepseek-harness/tree/571902028a75c64c1d767f4ae5fd099485f0ddf0)：持续工具循环、完整工具批次和用户数据形式的上下文检查点。
- [OpenCode，固定提交 3aa26f1](https://github.com/anomalyco/opencode/tree/3aa26f167660b46d61cbf44c52aa37c0a14bdc27)：工具详情折叠、自动整理与超限恢复、异步模型配置回执。
- [LiteLLM 模型管理接口](https://docs.litellm.ai/docs/proxy/model_management)与[OpenAI Chat Completions 参数](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)：目录能力和实际请求参数分别处理。

上游没有一套通用默认值。LoliCode 保留 `build + ask`，不因参考 OpenCode 自动放开权限，也不直接启用 DSH 依赖额外审查器的 Auto 语义。ZCode 对单次用户任务冻结模型；本产品按用户要求在下一次模型请求使用新配置。摘要阈值、标题预算及思考默认值也没有冒充与三个上游完全一致。

## 开发与验证

日常运行 `pnpm dev`：前端由 Vite 热更新，Rust 修改由 Tauri 增量编译并重新启动开发实例，无须每次制作安装包。安装好的旧版本不会因源码修改自动更新。

回归覆盖超过旧上限的连续工具任务、反复摘要后续接、原文/差异保留、重启恢复、取消/失败不重放、运行中配置、标题并发，以及折叠和后台轮询。模型端采用本机 HTTP 夹具，文件工具执行真实临时目录读写；LiteLLM 的公司目录仅做只读查询，没有对公司模型发起收费推理探测。这些证据不替代三端发行和所有真实模型协议的验收。
