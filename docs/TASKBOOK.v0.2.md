## 1. 背景与产品价值

免费 API 的模型、配额、注册门槛和可用地区分散在各供应商，且会变化。用户需要重复注册、查文档、维护 Key 和客户端配置；失败时难以区分网络问题、账户问题与服务问题。

FreeHub 的价值是“可信渠道目录 + 中文接入指引 + 本地凭据管理 + 有边界的故障切换”。目录信息必须附官方来源与核实记录，不以免费渠道数量或未经验证的竞争优势作为产品承诺。

### 1.1 目标用户

- 希望使用自己注册的免费模型渠道的开发者、学生和个人用户。
- 需要在已支持的 AI 客户端之间复用本地网关配置的人。
- 编程客户端用户属于后续兼容对象，能否支持取决于协议适配和具体模型的工具调用能力。

## 2. 目标、范围与产品约束

### 2.1 目标

1. 用户通过 `http://127.0.0.1:4310/v1` 和一个本地令牌访问已启用、已验证的模型。
2. M0 打通一个真实渠道；M1 完成至少三个真实渠道的接入、测试和注册指引。智谱、硅基流动、Groq 是首批候选，不保证其每个模型都免费或对所有地区可用。
3. 用户已完成供应商注册且有有效 Key 时，接入指引以 5 分钟内完成网关配置为体验目标。短信、实名审核、地区限制和供应商排队时间单独记录。
4. 对明确配置了备用路由的请求，在允许重试的错误发生且尚未向客户端提交响应时自动切换；已输出的流式请求不重新执行。
5. 目录更新不需要重装客户端；更新失败时保留最近一次有效目录，手动配置继续工作。

### 2.2 范围约束

- 用户使用现成聊天或编程客户端；FreeHub 提供渠道管理界面，不建设聊天产品。
- 上游 Key 与用户对话只经过用户本机和所选供应商。平台服务器提供目录、软件更新以及后续可选授权和健康汇总。
- 不托管、共享或出售上游账户、Key 和模型额度；只聚合用户合法取得的凭据。
- 免费模式只路由到用户确认的免费模型；余额充值、试用赠金和超额计费必须单独提示，不自动回退到付费模型。
- M0/M1 只实现 OpenAI Chat Completions 兼容出口。供应商特殊签名、原生 Gemini 等出口另设任务。
- M0/M1 的 Windows 验收通过后，再安排 macOS/Linux 及各自系统凭据库适配。

### 2.3 客户端兼容矩阵

| 对象 | 阶段 | 接入要求 | 对外承诺边界 |
|---|---|---|---|
| Cherry Studio | M0/M1 | Chat Completions、模型列表、SSE | 记录实际测试的版本、渠道、模型和通过用例 |
| LobeChat、OpenCode 等 | 后续逐项验证 | 检查实际版本使用的协议及工具调用格式 | 未执行真实客户端用例前标记“待验证” |
| Codex | P2 独立兼容任务 | `/v1/responses`，文本、工具调用、工具结果与流式事件转换 | 当前官方配置只支持 `wire_api = "responses"`；仅有 Chat Completions 不构成兼容 [R1] |
| Claude Code | P2 独立兼容任务 | Anthropic 格式入口、所需端点/请求头、工具调用与流式事件 | 官方不支持通过网关路由到非 Claude 模型；相关实验适配标注为第三方兼容实验，不承诺官方支持 [R2] |

协议格式兼容不等于模型能力相同。模型缺少工具调用、多模态或所需上下文长度时，必须明确报错，不伪造能力。

## 3. 架构与技术选型

### 3.1 数据流

```text
用户的 AI 客户端 → 本机网关 127.0.0.1:4310 → 用户配置的上游供应商
                         ↑
                  FreeHub 桌面管理界面
                         ↓
              本地 SQLite / 系统凭据库

FreeHub 桌面管理界面 → HTTPS 控制服务：目录、更新、后续授权
```

### 3.2 技术栈

| 部分 | 选型 | 实现约束 |
|---|---|---|
| 桌面壳与界面 | Tauri 2 + React + TypeScript | 首发 Windows；凭据操作通过受限 Tauri 命令进入 Rust，不由 WebView 直接转发模型请求 |
| 本地网关 | Rust + axum + reqwest 流式客户端 | 首版嵌入 Tauri 主进程，通过独立 crate 保持可测试性；启动/退出与应用生命周期一致 |
| 本地存储 | SQLite + Windows Credential Manager | SQLite 保存配置、凭据引用和请求元数据；真实 Key 保存到系统凭据库 |
| 目录发布 | Nginx 静态 JSON | M1 优先使用版本化静态目录；客户端内置种子数据和有效缓存 |
| 后续控制服务 | Node.js + TypeScript + Hono + SQLite | 复用当前服务器 Node.js 环境；systemd 管理，服务绑定回环地址，由 Nginx 提供 HTTPS [R6] |
| 构建与分发 | 本地 Windows / CI + 安装包 | 开发环境需要 Rust、MSVC 构建工具及 WebView2；macOS 构建另设对应环境 [R5] |

Cloudflare Workers 等托管方式保留为迁移选项，不在首版同时维护两套控制服务。

### 3.3 项目结构与部署位置

源代码使用独立仓库，建议结构：

```text
apps/desktop/              # Tauri 壳、管理界面与应用生命周期
crates/gateway/            # 路由、鉴权、SSE、错误分类、模型映射
catalog/                  # 渠道目录、注册指引、Schema、证据记录
services/control-plane/   # 后续目录 API、授权、健康汇总
tests/                    # 模拟上游、协议用例、客户端验收记录
docs/                     # 安装、兼容矩阵、运维与恢复说明
```

服务器任务书位置保持 `/www/wwwroot/free-gateway/TASKBOOK.md`。部署时单独创建静态发布目录，只暴露目录 JSON、安装包和公开文档；源代码、任务书、数据库、备份和密钥文件不作为静态站点内容发布。

后续控制服务可预选 `127.0.0.1:4311`，上线前重新检查端口占用。域名、DNS、证书与具体发布路径在目录服务上线任务中落实，不把候选地址写成已上线地址。

### 4.1 P0 / M0：最小真实链路

| 功能 | 实现要求 | 验收 |
|---|---|---|
| 网关生命周期 | 只监听 IPv4 回环 `127.0.0.1`，默认端口 4310；占用时明确提示 | 启动与退出行为正确，其他网卡无法访问；不存在重复网关实例 |
| 本地鉴权 | 安全随机生成 `sk-freehub-*` 令牌，支持轮换；模型列表和推理接口均鉴权 | 缺失/错误令牌返回 401，不发送上游请求 |

## 5. 网关、模型路由与凭据规则

### 5.1 接口与超时

- M0/M1 的协议版本为 OpenAI Chat Completions 子集，支持范围写入兼容说明。`/v1/responses` 和 `/v1/messages` 在实现前返回明确的未支持错误，不返回伪成功。
- `/v1/models` 返回本机已启用且可路由的公共模型 ID；模型目录结果不视为调用权限证明。
- `/health` 仅返回网关运行状态和协议版本，不暴露渠道地址、凭据或用户配置。
- 连接超时默认 10 秒，响应头/首字节等待默认 60 秒，流式空闲超时默认 120 秒；均可配置。M1 默认请求总预算 120 秒，流式从首个有效事件后采用空闲超时。
- 设定请求体上限、并发上限和队列上限；拒绝超限请求时返回明确原因。初始默认值在 M0 测试后确定并记录。
- 客户端断开/取消时立即取消上游请求并释放资源；背压传递到上游，避免无限缓冲。

### 5.2 模型标识与能力

1. 默认公共 ID 为 `provider-id/model-id`，可追溯到具体渠道与上游模型，避免误合并同名模型。
2. 同一实际模型多渠道可配置显式别名；每条备用路由记录上游模型 ID、供应商和支持能力，不能仅凭字符串相似度合并。
3. 跨实际模型降级是单独设置，默认关闭。用户开启时明确告知模型会变化；响应与日志记录实际提供结果的模型，不伪装成原模型。
4. 路由前检查工具调用、模态、上下文和免费模式限制；不支持的能力不静默丢弃。
5. 目录更新不得自动改写已有渠道的 Base URL、模型映射或启用付费模型。变更进入可查看的更新差异，由用户主动应用。

### 5.3 重试与冷却

| 失败类别 | 行为 | 状态作用域 |
|---|---|---|
| 本地令牌错误/本地请求无效 | 立即返回，不请求上游 | 当前请求 |
| 上游 401、已明确识别的凭据/权限错误 | 标记凭据待修复；有兼容备用渠道且响应未提交时可切换 | 用户本地渠道；更换 Key 后重新测试，不靠定时重试反复消耗 |
| 上游 429 | 区分短时限流与配额耗尽；遵循有界 `Retry-After` 或已知配额重置时间，尝试兼容备用渠道 | 用户本地渠道/模型；信息不足时显示未知重置时间 |
| 上游 5xx、网络失败或超时 | 在总预算内尝试兼容备用渠道 | 用户本地渠道；临时故障默认冷却 5 分钟，连续失败指数退避，上限 30 分钟 |
| 参数错误、上下文超限、内容拒绝或无法分类的 403/4xx | 返回明确错误，不靠轮换渠道掩盖问题 | 当前请求 |
| 客户端取消 | 取消上游，不切换 | 当前请求 |
| 已提交响应后失败 | 记录部分失败，按协议结束或报告错误，不重新执行请求 | 当前请求 |

每个候选渠道每次请求最多尝试一次，避免往返循环；优先级顺序确定，重试总次数不超过兼容候选数，等待受总预算限制。

流式请求在已检查成功状态且收到首个有效事件前不向客户端提交响应头；必要时短暂缓冲。提交响应头后即不切换，上游输出的文本、工具参数片段或其他有效事件都计入已提交内容。上游自带 ping/空行不能误判为有效内容。中途失败由客户端发起新的请求，FreeHub 不自动重放。

M1 验证非流式工具调用及流式工具参数片段的透传。一次普通对话成功不作为工具调用兼容的证明。

### 5.4 凭据与本地访问

- 上游 Key 只写系统凭据库；SQLite 保存凭据条目引用。凭据只在调用期间进入必要的进程内存，界面回显为遮蔽内容。
- 本地聚合令牌与上游 Key 是两种凭据。聚合令牌用至少 32 字节安全随机数生成；网关仅持久化校验摘要，桌面应用需要回显令牌时从系统凭据库读取。
- 用户复制聚合令牌到第三方客户端后，其保存方式由该客户端决定；不承诺“第三方配置文件也没有任何明文令牌”。聚合令牌仍须脱敏、可轮换，不能据此读取或导出上游 Key。
- 模型接口只接受本地令牌；管理操作使用受限 Tauri 命令，不与模型令牌共享管理权限。阻止不受信任 Origin 的浏览器调用，不开放任意跨域。
- 默认上游要求 HTTPS；拒绝 URL 内嵌用户名/密码。不携带 Authorization 跟随跨主机重定向。
- 原始上游错误体可能包含提示词或凭据，只转换为受控类别和安全描述，不能直接写日志、遥测或界面。
- 目录和软件更新签名使用不同用途的密钥；授权签名密钥不用于更新发布。

## 6. 渠道目录、核实与健康观测

### 6.1 三类状态

| 信息 | 保存位置 | 含义 |
|---|---|---|
| 目录核实状态 | 云端目录与客户端缓存 | 官方条款、免费模型、注册条件和接入证据是否完成核实 |
| 本地调用状态 | 用户本机 | 该用户的 Key、套餐、地区、网络和选定模型在本机是否可用 |
| 汇总观测 | 后续可选控制服务 | 一段时间、一定地区与样本数内的成功/错误/延迟统计，不保证每个用户可用 |

目录核实状态使用 `candidate / verified / retired`。无充分证据时保留 `candidate`；本地失败不会自动把公共渠道标为 `retired`。

### 6.4 更新与核实流程

1. 收集官方价格、模型、限额、注册和使用条款，记录 URL 与核对日期。
2. 对拟启用模型执行经用户允许的本机测试，分别记录流式、工具调用、权限与免费条件，不把模型列表查询成功当作推理成功。
3. 校验 Schema、唯一 ID、协议、HTTPS URL、免费分类、证据字段与核实状态；无证据不得升级为 `verified`。
4. 生成版本化 JSON 和差异；审阅重要端点、价格/免费条件和退休状态变更后发布。签名更新启用前先配置可信公钥。
5. 客户端校验体积、版本、Schema、签名（启用后必验），再原子替换缓存；不受信任或失败更新保留上一版。
6. CI 定期校验数据与官方网页可达性。网页可达只证明页面可读；CI 不持有用户 Key，也不伪称已验证用户账户的推理健康。

### 6.5 本地探测与可选上报

- M0 提供用户主动“测试连接”；M1 优先利用实际请求被动更新状态。
- 定时推理探测默认关闭；用户开启时说明将消耗供应商配额，默认间隔 30 分钟，可调整或关闭。仅测已启用、已确认免费的模型。
- 探测参数按模型能力配置，不统一强制 `max_tokens=1`；部分模型的推理预算、最小输出长度和接口参数需要单独处理。
- 后续健康上报默认关闭，由用户主动开启。仅允许预定义渠道 ID、受控结果类别、粗粒度延迟与大范围地区；不发送 Key、提示词、正文、原始错误、完整 URL 或自定义渠道名称。
- 不能承诺严格匿名：网络接收方仍可能看到 IP。服务端应限制访问日志留存，不收集稳定设备 ID；展示采样时间、地区、样本数和置信边界，防止单个错误样本改写公共状态。

## 7. 里程碑与验收

工期是计划估计，不是完成承诺；按每阶段结果重新评估。跨协议与多平台扩展不计入首个 Windows MVP 的工期。

### 7.1 M0：一个真实渠道，预计 1 周

开发顺序：Windows 构建环境 → Tauri 壳和 gateway crate → 凭据/本地鉴权 → 非流式调用 → SSE → Cherry Studio 实测。

全部通过后才能标记 M0 完成：

1. 干净 Windows 环境可安装并启动；网关只绑定 `127.0.0.1:4310`，端口冲突和重复实例有明确提示。
2. 错误/缺失本地令牌返回 401，模拟上游收到的请求数为 0。
3. 一个已确认免费且当前账户可用的真实模型，非流式与 SSE 调用均成功。
4. Cherry Studio 指定测试版本，配置本地地址与令牌后连续完成多轮流式对话。
5. 退出、重启后凭据可用；数据库、配置、日志、临时文件与缓存扫描不到测试上游 Key 和注入的正文标记。此检查验证应用持久化行为，不宣称进程内存不存在凭据。
6. 上游失败、超时、坏 Key、客户端取消、应用退出均正确释放请求；敏感上游错误回显经过过滤。
7. 提交可复现验收记录：平台/客户端版本、渠道/模型、时间、用例结果；请求内容只使用测试文本，不保存真实用户对话。

### 7.2 M1：三个渠道的 MVP，预计 2–3 周

- 完成第 4.2 节全部能力；三个渠道分别真实可用。
- 模拟上游可重复验证 401、429、5xx、超时、流式中断、工具片段、取消和不支持能力；覆盖重试前后边界。
- 切换成功时记录实际渠道/模型；切换失败时明确报错；已提交的流不重放。
- 目录至少更新一次无需重装；离线、损坏目录和端点变更不会破坏现有配置。
- 在本人实际使用中持续观察至少 7 天，记录遇到的问题与修复；供应商停机和账户额度耗尽与应用故障分别统计。

### 7.3 M2：Windows 公测，预计 1–2 周

### 8.3 安全与运营约束

- 控制服务不接收上游 Key、对话内容或推理请求；日志、遥测和错误处理采用字段白名单。
- 网关只允许回环监听，模型令牌不能调用管理操作。操作系统被攻陷不属于本地令牌能完全防御的范围。
- 目录签名、端点变更审阅、软件更新签名和凭据库测试都是独立验收项，不以“仅在本机”替代这些检查。
- 原稿关于备案、生成式 AI 服务分类、营业执照、电信许可、支付和税务的结论未完成专项核实，本版不将其作为已确认前提。对外发布和收费前，按实际运营主体、部署地区、产品功能与平台要求另行核实并记录来源。
- 供应商条款、地区限制和免费条件必须在指引中如实呈现；不把“用户自行遵守”当作忽略平台自身义务的理由。

## 10. 授权、Pro 与支付（基础网关稳定后实施）

### 10.1 免费版与 Pro 的边界

- 免费版包含本任务书 P0 的完整能力：本地网关、渠道管理、系统凭据存储、基本注册指引、基本目录更新、显式模型映射和故障切换。渠道数量不人为限制。
- 后续已验收的基础协议兼容按免费基础网关能力规划，避免把支持目标客户端所必需的功能同时宣传为免费和 Pro 独占。
- Pro 的候选价值是批量客户端配置与备份恢复、高级本地统计报表、额外情报提醒等效率功能。收费功能、价格和支持范围在实现后单独确定，不出售供应商免费额度。
- Pro 未激活、到期、控制服务不可达或许可校验失败时，只影响对应 Pro 功能，已配置的免费基础网关继续工作。

### 10.2 授权设计

- 后续接口包括 `POST /v1/license/activate` 和 `POST /v1/license/refresh`；签发含版本、许可 ID、功能集合、有效期和宽限截止时间的 Ed25519 签名令牌。
- 私钥保存在服务端受保护存储；客户端只内置公钥。卡密不进入 URL、访问日志或普通日志，服务端持久化用可验证摘要代替明文卡密。
- 设备绑定使用最少必要信息；说明其用途和换机/解绑流程，不将授权设备标识混入健康上报。
- 在线校验建议至少每日一次。离线宽限最长 7 天，令牌中的硬截止时间受订阅到期约束；宽限结束后暂停 Pro 功能，基础网关可用。
- 吊销在下一次成功在线校验时生效；持续离线用户最多在已有签名令牌的有效宽限内继续使用 Pro，不能承诺离线即时吊销。
- 明确测试令牌篡改、过期、重复激活、换机、时钟回拨、控制服务断线与密钥轮换；记录本地离线校验的实际限制。

### 10.3 支付候选与实施门槛

原稿的爱发电、面包多、虎皮椒、微信/支付宝商户方案、Paddle 和 Lemon Squeezy 仅保留为候选。费率、准入、主体资格、自动发货、地区、退款和税务处理以实施时官方规则及实际账户条件为准，本版不沿用固定价格、审核时长或“个人天然合规”的断言。

实施前完成具体方案评审；支付接入必须验证回调签名、订单金额/币种与状态，使用幂等发货和退款/吊销联动。支付平台不持有授权签名私钥，不用支付成功页面访问本身作为发货凭证。
