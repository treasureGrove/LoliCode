## 2. 体验目标

产品名称：**LoliCode**。

体验关键词：连续、跟手、轻盈、安静、精致、优雅。有艺术感，但日常管理模型和渠道必须高效。

“类似 iPhone”的含义是操作与画面变化之间有自然的因果关系：按下立即有反馈；卡片进入详情能看出来自哪里；关闭能感知回到哪里；浮层有明确的空间层级；快速反向操作可以自然接续。不能仅靠大圆角、毛玻璃或所有页面统一淡入来代替这些交互。

这是 Windows 桌面应用，应适配鼠标、键盘、滚轮和窗口缩放。借鉴手机的运动品质，不把桌面软件做成一部放大的手机，也不要求用户依赖触屏手势才能完成操作。

### 太极的表达

- 从阴阳平衡、虚实、留白、圆弧与流动建立视觉语言。
- 宣纸与玄墨可以继续作为探索起点，色彩、字体和布局允许重新设计。
- 朱砂或低饱和玉色作为有限的强调色，明确主次，不到处发光。
- 标志和关键转场可以使用太极意象，避免铺满八卦装饰、持续旋转和廉价水墨特效。
- 艺术感来自比例、排版、材质和运动的一致性。正文、数值、错误提示必须清晰。

## 4. 建议的信息架构与页面方向

以下是可落地的设计起点，不是已经验收的最终设计。接力者应结合实际页面复杂度，形成一套一致方案后直接推进实现。

### 应用外壳

- 把“当前正在管理哪个客户端”和“当前正在做什么”分成两个清晰层级，减少现有长侧栏的工具堆叠感。
- 当前客户端可以作为明确的切换器；主导航聚焦工作台、配置资源、用量和设置等任务。先制作完整功能映射，确保调整分组后每个已有入口可达。
- 导航保留稳定锚点。上下文变化通过标题、选择指示和内容关系表达，避免整屏同时飞动。
- 兼顾紧凑窗口与大窗口；狭窄时合理收拢次要信息，主要操作和当前状态始终可见。

### 供应商工作台

- 从“可用渠道、当前使用、健康／连接状态、下一步操作”组织层级，减少等权按钮。
- 主要卡片可打开详情面板。若采用卡片到详情的形态过渡，返回必须恢复原列表位置、筛选与选中项。
- 常用切换动作保持直接；管理、编辑、复制等放在明确的次级位置。不要为展示动画增加操作步数。
- 状态信息来自真实接口。没有健康或余额数据时显示未知／未检测，不能编造绿色正常状态。

### 新增与编辑

- 设计连贯的弹层或面板流程：选择来源 → 填写／调整 → 校验与保存。简单场景可在一屏完成，不强行做多步向导。
- 保留复杂渠道的高级配置能力，采用渐进展开，但不能丢字段、默认值或客户端专属选项。
- 动效不得导致输入框失焦、光标跳动、自动选中文字或草稿重置。
- 关闭请求先走草稿保护；只有真正确认关闭后才结束内容生命周期。

### 统计与设置

- 统计先突出可解释的关键值，再提供明细和过滤。数值变化需与真实数据更新一致。
- 设置可以采用层级面板和分组列表；返回保持上下文和滚动位置。
- 图表动画只辅助理解变化，避免每次切页都从零播放长动画。

## 5. 动效系统：具体到每一种操作

建立统一的 motion tokens、过渡容器与交互状态约定。下表是建议初始值，需要在真实 WebView2 中调校，**不是 Apple 官方参数，也不是已经测得的性能结果**。

| 场景 | 期望体验 | 建议起点 | 必须满足 |
| --- | --- | --- | --- |
| 按钮按下／松开 | 当下就响应，释放轻柔回位 | 按下缩放 0.97–0.99；释放约 140–220ms | 键盘也有反馈，禁用态无可点击错觉 |
| 分段控件 | 选中底板移动到新位置，内容连续切换 | 约 220–320ms 的低回弹弹簧 | 快速连续切换从当前位置接续，不排队 |
| 同层页面切换 | 方向克制，焦点和结构稳定 | 约 180–280ms，小位移加透明度 | 不重置草稿，不让整页重复挂载 |
| 列表进入详情 | 保持来源与去向的空间关系 | 约 280–420ms，共享元素／容器过渡 | 返回原位置；有简单降级方案 |
| 弹层打开与关闭 | 前景浮起、背景后退，层次清楚 | 约 240–360ms，小幅位移和尺度变化 | 焦点限制、Esc、滚动锁、焦点返回正确 |
| 卡片重排 | 对象跟随操作，其他项自然让位 | 布局动画约 180–280ms | 不与拖拽 transform 冲突，不误触打开 |
| 展开高级选项 | 内容有延续感，阅读位置稳定 | 约 180–260ms，局部布局过渡 | 长表单不持续触发全页重排 |
| 加载与结果 | 操作立即被接收，再交代真实结果 | 即时按下反馈；等待稍长再显示加载提示 | 防重复提交；成功只能在操作成功后出现 |
| 主题切换 | 材质和颜色平滑变化 | 约 160–260ms，局部过渡 | 无闪白；不做昂贵全屏模糊动画 |

### 必须统一的运动规则

- 优先使用低回弹、短距离的弹簧。避免橡皮筋式夸张弹跳、长延迟和全站固定 500ms 慢动作。
- 动画可中断、反转与重定向。以用户最新意图为准，不能必须等上一段播完。
- 导航、动画、数据加载分开管理：动画不阻塞请求，请求完成也不强制重播进场。
- 交互对象离场后不能继续接收点击；退场残留元素不得制造重复可访问节点和重复 ID。
- 优先动画 `transform` 和 `opacity`，限制大面积 blur、阴影和复杂滤镜。
- 不覆盖系统滚动、不制造滚轮惯性模拟、不劫持系统边缘手势。
- 不用大量常驻 `will-change` 或无限动画假装流畅；仅对必要元素临时开启优化。
- 支持 `prefers-reduced-motion`：移除空间位移、形变和弹跳，保留必要的简短状态反馈。
- 主题、导航、弹层、拖拽不能各自叠加一套互相打架的动画。

## 7. 推进顺序与阶段产物

### A. 功能盘点与设计骨架

读取当前实现，列出全部导航入口、主要操作、特殊客户端和危险操作。输出旧入口到新入口的映射，以及页面层级、组件规范和运动规则。设计产物要明确到结构与行为，不能只写形容词或出一张首页图片。

### B. 完成一个真实纵向流程

优先实现：启动 → 选择客户端 → 查看供应商 → 打开详情／编辑 → 处理未保存草稿 → 返回 → 切换模式 → 查看用量。

这条流程应使用真实应用组件和原业务接口，形成可以实际操作的桌面版本。用它验证整套设计是否显著区别于上一版；继续实施时不把静态概念图当成交付。

### C. 推广到全部页面与状态

迁移其余页面和基础组件，清理重复样式与旧动画。逐项覆盖空、加载、失败、禁用、选中、编辑中、保存中和窄窗口状态。对尚未迁移的页面明确登记，不隐藏或删除它们。

### D. 实机验证与交付

完成类型检查、相关行为测试、生产构建和原生检查；录制主要操作的连续视频。最终输出新 EXE、安装包、设计／动效说明、验证记录和已知限制。

## 8. 验收标准：不能只看截图

### 视觉与交互

- 与 `beef33d` 对比，能明确指出信息架构、主要布局、组件形态和关键操作路径的实质变化。
- 有完整、统一的明暗主题。太极表达精致而克制，主要任务和内容比装饰更突出。
- 能连续演示至少 6 类真实交互：导航、分段切换、详情进退、表单开关、列表操作、状态反馈。
- 连续快速操作至少 10 次仍能正确响应最新意图，无动画排队、残影、卡死、错位或重复动作。
- 新增／编辑中尝试离开，选择继续编辑后字段、光标行为与草稿正确；确认放弃才丢弃草稿。
- 返回列表保留合理的滚动、筛选与选择上下文；动画期间不误触底层内容。

### 窗口、无障碍与性能

- 在真实 Windows WebView2 验证默认 `1000×650`、最小 `900×600` 和较大窗口；另检查 125%／150% 系统缩放。主要操作、表单底部和窗口控制不能溢出。
- 支持 Tab、Shift+Tab、Enter、Space、Esc；焦点可见、浮层焦点正确、关闭后焦点返回合理。
- 减少动态效果模式下功能完整；明暗主题和高对比下文字及操作状态可辨认。
- 以目标机器 60Hz 下接近持续 60fps 为调优目标，约 16.7ms 的帧预算只是目标。记录实际环境和采样结果，不能把 CSS 时长当作帧率证据。
- 检查代表性交互的性能轨迹：明显掉帧、长任务、布局抖动、重复请求和多余重渲染；发现问题应优化或降级。
- 鼠标点击应立即产生可感知反馈，操作完成时间由真实业务决定，不用假成功掩盖等待。

### 证据与业务回归

- 静态截图用于看视觉；连续录屏用于看动效。至少包含明暗主题、连续导航、模式切换、表单草稿保护和窄窗口。
- 浏览器模拟预览必须标明示例数据，不能冒充真实原生体验。最终至少有 Windows 原生交互证据；若工具无法录制或检查，明确留下待验证项，不编造通过。
- 用临时配置测试，不读出或展示 Key，不未经授权发起付费请求。
- 对改变的生命周期、导航、状态保持及关键交互补充有意义的测试；避免仅断言类名或动画参数的形式测试。
- 全量前端回归应通过；原生代码或业务契约若改动，应扩大相应后端回归。旧测试通过记录不能当作新实现的测试结果。
